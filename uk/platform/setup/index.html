Встановлення svitlo-provider

Перетвори вільну GPU (чи навіть CPU) на compute-провайдера Svitlo Chain. На цій сторінці — ті самі чотири етапи для кожної ОС: завантаження, гаманець, залежності, запуск — з точними командами для macOS, Linux і Windows. Що саме робить svitlo-provider — дивись на сторінці Платформи.

Етап 1

Завантаження

Один файл під твою ОС — жодного інсталятора запускати не треба.

Етап 2

Гаманець

Створюється provider-ключ — окремий простий секрет, не твій звичайний гаманець.

Етап 3

Залежності

Python + PyTorch довантажуються під час встановлення — не входять у сам файл.

Етап 4

Запуск

Реєстрація в оркестраторі, автовизначення заліза, початок прийому задач.

Інструкції для встановлення

🍎 macOS · Автоматично

Apple Silicon і Intel — одна команда

Один рядок робить усі чотири етапи одразу: завантажує бінарник, створює provider-гаманець (запитає пароль просто в терміналі), встановлює PyTorch і реєструє launchd-агент, щоб провайдер стартував при вході в систему й перезапускався у разі падіння.

curl -fsSL https://www.svitlochain.com/downloads/install-provider-macos.sh | bash
💡 Запускай саме через curl у Терміналі, а не завантажуючи файл браузером. У цього репозиторію ще немає платного сертифіката Apple Developer ID, тож файл, завантажений браузером, отримає мітку com.apple.quarantine і Gatekeeper відмовиться його запускати. Завантаження через curl такої мітки не ставить — тому один рядок повністю обходить цю проблему.

Логи: tail -f ~/.svitlo/logs/provider.log  ·  Зупинити: launchctl unload ~/Library/LaunchAgents/com.svitlochain.provider.plist

🐧 Linux · x86_64

Вручну, чотири команди

Завантаж svitlo-provider і svitlo-wallet, далі:

chmod +x svitlo-provider-linux-x86_64 svitlo-wallet-linux-x86_64 # 1. Створити гаманець (запитає пароль, покаже 24-словну recovery-фразу # ОДИН РАЗ — запиши її, вона ніде більше не зберігається й не показується) ./svitlo-wallet-linux-x86_64 keygen --output wallet.json # 2. Експортувати у простий формат, який читає svitlo-provider ./svitlo-wallet-linux-x86_64 export-provider-key --wallet wallet.json --output provider-wallet.json # 3. Перевірити, яке залізо бачить, і почати приймати задачі ./svitlo-provider-linux-x86_64 detect ./svitlo-provider-linux-x86_64 start --node https://rpc.svitlochain.com --wallet provider-wallet.json

Запусти під systemd (user-сервіс або звичайний nohup), якщо потрібно, щоб процес пережив вихід із сесії — готовий systemd-юніт у планах.

🪟 Windows · x86_64 · Windows 10+

Вручну, ті самі три кроки

Завантаж svitlo-provider-windows-x86_64.exe. Windows-збірки svitlo-wallet поки немає, тож згенеруй provider-wallet.json на Linux чи macOS (див. відповідні вкладки) і перенеси його сюди, далі з PowerShell чи cmd:

svitlo-provider-windows-x86_64.exe detect svitlo-provider-windows-x86_64.exe start --node https://rpc.svitlochain.com --wallet provider-wallet.json

Потрібна Windows 10 або новіша — збірка таргетить x86_64-pc-windows-msvc, який вимагає Windows 10+ починаючи з Rust 1.78. Додай до Планувальника завдань (запуск при вході), якщо хочеш, щоб процес переживав перезавантаження без ручного старту.

FAQ

Навіщо потрібні Python і PyTorch?

Сам бінарник провайдера написаний на Rust, але реальну роботу з моделями виконує невеликий Python-скрипт-воркер — саме PyTorch виконує обчислення на GPU. Він встановлюється через pip, а не входить у файл, щоб завантаження лишалось на кілька мегабайт, а не гігабайт, і щоб ти завжди отримував PyTorch, підібраний під твою конкретну конфігурацію CUDA/ROCm/MPS. Inference-воркер довантажується автоматично; training-воркер зараз доступний лише затвердженим тестувальникам (лише за запрошенням — увійти, якщо маєш акаунт), поки технологія моделей готується до патентування.

Provider-гаманець — це те саме, що мій звичайний гаманець Svitlo?

Ні — svitlo-provider потребує provider keyfile (простий секретний ключ), а не зашифрований wallet.json твого звичайного гаманця. svitlo-wallet export-provider-key робить такий ключ зі звичайного гаманця, або macOS-інсталятор створює обидва одразу. Тримай provider-wallet.json приватно — це твій підписуючий ключ.

Як зупинити чи видалити?

macOS: launchctl unload ~/Library/LaunchAgents/com.svitlochain.provider.plist, потім видали ~/.svitlo і файл .plist для повного видалення. Linux/Windows: зупини процес (Ctrl+C або як там ти його запустив) і видали бінарник та файли гаманця.

Де подивитись логи?

macOS (інсталятор): ~/.svitlo/logs/provider.log. Linux/Windows: туди, куди перенаправив stdout/stderr під час запуску — за замовчуванням процес пише в консоль.

Чи можна підключити до власної ноди замість публічної мережі?

Так — передай URL своєї ноди у --node замість https://rpc.svitlochain.com.
