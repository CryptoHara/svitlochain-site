Setup guide

Install svitlo-provider

Turn a spare GPU (or CPU) into a Svitlo Chain compute provider. This page walks through the same four stages on every OS — download, wallet, dependencies, running — with the exact commands for macOS, Linux, and Windows. See the Platform page for what svitlo-provider actually does.

Stage 1

Download

Grab the binary for your OS — one file, no installer to run first.

Stage 2

Wallet

Create a provider signing key — a plain secret, separate from your regular wallet.

Stage 3

Dependencies

Python + PyTorch, fetched at install time — not bundled into the download.

Stage 4

Running

Registers with the orchestrator, auto-detects your hardware, starts polling for jobs.

Setup instructions

🍎 macOS · Automatic

Apple Silicon & Intel — one command

A single line handles every stage above: it downloads the binary, creates your provider wallet (prompting for a password right there in the terminal), installs PyTorch, and registers a launchd agent so the provider starts on login and restarts if it ever crashes.

curl -fsSL https://www.svitlochain.com/downloads/install-provider-macos.sh | bash
💡 Run this from Terminal via curl, not by downloading the file in a browser first. This repo doesn't yet hold a paid Apple Developer ID certificate, so a browser download gets tagged com.apple.quarantine and Gatekeeper refuses to run it. A curl fetch never sets that tag, so the one-liner sidesteps the problem entirely.

Logs: tail -f ~/.svitlo/logs/provider.log  ·  Stop: launchctl unload ~/Library/LaunchAgents/com.svitlochain.provider.plist

🐧 Linux · x86_64

Manual, four commands

Download svitlo-provider and svitlo-wallet, then:

chmod +x svitlo-provider-linux-x86_64 svitlo-wallet-linux-x86_64 # 1. Create a wallet (prompts for a password, shows a 24-word recovery # phrase ONCE -- write it down, it's never stored or shown again) ./svitlo-wallet-linux-x86_64 keygen --output wallet.json # 2. Export it into the plain-secret format svitlo-provider reads ./svitlo-wallet-linux-x86_64 export-provider-key --wallet wallet.json --output provider-wallet.json # 3. Check what hardware it sees, then start polling for jobs ./svitlo-provider-linux-x86_64 detect ./svitlo-provider-linux-x86_64 start --node https://rpc.svitlochain.com --wallet provider-wallet.json

Run it under systemd (a user service or a plain nohup) if you want it to survive a logout — a packaged service unit is on the roadmap.

🪟 Windows · x86_64 · Windows 10+

Manual, same three steps

Download svitlo-provider-windows-x86_64.exe. There's no Windows svitlo-wallet build yet, so generate your provider-wallet.json on a Linux or macOS machine first (see those tabs) and copy it over, then from PowerShell or cmd:

svitlo-provider-windows-x86_64.exe detect svitlo-provider-windows-x86_64.exe start --node https://rpc.svitlochain.com --wallet provider-wallet.json

Requires Windows 10 or later — the build targets x86_64-pc-windows-msvc, which needs Windows 10+ since Rust 1.78. Register it in Task Scheduler (run on login) if you want it to survive a reboot without you starting it by hand.

What happens next

After you run start

→

Hardware is detected automatically

GPU backend (CUDA / ROCm / Apple MPS / CPU-only), VRAM, and core count — no manual configuration needed. Run detect on its own first if you just want to see what it reports.

→

It registers with the orchestrator

Your node becomes visible to the job-matching system at the --node address you passed — https://rpc.svitlochain.com for the public network.

→

It polls for jobs and executes them

Inference, image generation, speech-to-text, or tensor-training jobs get dispatched to your node when it matches the requirements and is free.

→

Earnings settle in SVIT, on-chain

Every completed job is cryptographically verified and paid out to your provider wallet automatically — no manual invoicing.

Questions

FAQ

Why does it need Python and PyTorch?

The provider binary is Rust, but the actual model-training/inference work runs through a small companion Python worker script (also downloaded automatically) — PyTorch is what does the real GPU math. It's fetched via pip rather than bundled so the download stays a few megabytes instead of several gigabytes, and so you always get a PyTorch build matched to your own CUDA/ROCm/MPS setup.

Is my provider wallet the same as my regular Svitlo wallet?

No — svitlo-provider needs a provider keyfile (a plain secret key), not the encrypted wallet.json your everyday wallet uses. svitlo-wallet export-provider-key derives one from a regular wallet, or the macOS installer creates both for you in one pass. Keep provider-wallet.json private — it's your signing key.

How do I stop or uninstall it?

macOS: launchctl unload ~/Library/LaunchAgents/com.svitlochain.provider.plist, then delete ~/.svitlo and the .plist file to remove it fully. Linux/Windows: stop the running process (Ctrl+C, or however you're supervising it) and delete the binary and wallet files.

Where are the logs?

macOS (installer): ~/.svitlo/logs/provider.log. Linux/Windows: whatever you redirected stdout/stderr to when you launched it — the process logs to the console by default.

Can I point it at a node I run myself instead of the public network?

Yes — pass your own node's URL to --node instead of https://rpc.svitlochain.com.
